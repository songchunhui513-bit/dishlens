# DishLens 点单/点过功能设计与研发约束

日期：2026-06-03

## 目标

在不破坏现网 H5 视觉和交互的前提下，新增“选菜、给店员核对、保存到点过、点过后评价”的完整旅程。

本功能是现网体验的增量，不是 redesign。

## 绝对约束

1. 不重做首页。
   - 首页主体结构保持现网：Header、天气/推荐理由、今日推荐、拍摄菜单、从相册选择、最近翻译、底部导航。
   - “点过”只能加入底部导航，与“历史 / 收藏 / 设置”同级。
   - 不在首页中部新增“点过卡片”“最近点过卡片”“功能说明卡片”。

2. 不重做翻译结果列表。
   - 保持现网 `ResultsPage` 菜品卡片结构、字体、图片尺寸、标签、推荐文案排版。
   - 只允许新增轻量选菜控件。
   - 不新增顶部点过摘要。
   - 不显示“几道菜品”统计。

3. 不重做菜品详情页。
   - 保持现网 `DishDetailPage` 结构：顶部返回 + 标题 + 收藏，hero 图片，菜名，原文，标签，风味特征，点单建议，食客评价。
   - 只允许在底部新增“已选/点单”模块。
   - 新增模块不得遮挡现有评价按钮、收藏按钮、正文内容。

4. 不重做给店员核对页视觉。
   - 使用现网暖色浅底、细边框、轻阴影。
   - 避免大面积深橙卡片。
   - “我已点好，保存到点过”不能做成过重的大绿按钮，推荐浅绿色底 + 细描边。

5. 点过页保持简洁。
   - “点过”页按餐厅/就餐批次聚合。
   - 不显示“点过几次”这类冗余 badge。
   - 餐厅记录卡片整卡可点进入详情。
   - 不放“查看这次点过”按钮。
   - 可保留轻量“评价餐厅/改餐厅评价”按钮。

6. 点过详情复用翻译列表。
   - 点过详情里的菜品列表必须沿用现网翻译结果列表卡片风格。
   - 只在卡片右上角新增轻量“评价/已评”按钮。
   - 点击菜品卡片进入现有菜品详情。

7. 不新增分享入口。
   - 本次点单/点过设计不新增分享按钮。
   - 不改现有分享逻辑。

## 建议落地文件范围

允许最小增量修改：

- `src/components/home/HomePage.tsx`
  - 底部导航新增“点过”。

- `src/components/results/ResultsPage.tsx`
  - 新增轻量选菜控件。
  - 保持原卡片结构。

- `src/components/dish/DishDetailPage.tsx`
  - 底部新增点单模块。
  - 保持原详情结构。

- 新增独立组件：
  - `OrderConfirmPage`
  - `OrderedPage`
  - `OrderedDetailPage`
  - 本地存储/状态 helper。

不应改动：

- 现网色彩 token。
- 现网字体 token。
- 现网结果卡片主布局。
- 现网详情页主布局。
- 现网分享组件。

## 验收标准

1. 首页截图对比现网：除底部新增“点过”入口外，主体不应变化。
2. 结果列表截图对比现网：除选菜控件外，不应出现新增顶部摘要或统计。
3. 详情页截图对比现网：除底部点单模块外，正文和顶部结构不应变化。
4. 给店员核对页视觉应轻，不能出现重橙卡片和重绿主按钮。
5. 点过页点击餐厅卡片进入点过详情。
6. 点过详情菜品卡与翻译结果列表一致，并带评价按钮。
7. 通过移动端宽度 393px 截图检查，无遮挡、无错位、无横向溢出。
