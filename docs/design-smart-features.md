# DishLens 智能推荐 + 历史 + 收藏 — 设计文档

> 版本：v1.0 | 日期：2026-05-23
> 设计规范：v7 Warm Editorial
> 平台：H5 网页版（393×852 viewport）
> 存储：localStorage（无用户登录体系）

---

## 一、设计目标

将首页「今日推荐」、翻译历史、菜品收藏从 mock/硬编码状态升级为真实数据驱动：

| 功能 | 当前状态 | 目标状态 |
|------|---------|---------|
| 今日推荐 | 硬编码 Boeuf Bourguignon | 基于时间/天气/地区智能推荐，每天自动换 |
| 附近推荐 | 暂无 | 基于地理位置推荐附近餐馆，并引导到店拍菜单后推荐具体菜品 |
| 翻译历史 | 4 条 mock 数据 | localStorage 存储真实翻译记录 |
| 菜品收藏 | 3 条 mock 数据 | localStorage 收藏，详情页心形联动 |
| 最近翻译 | 3 条硬编码 | 从历史记录取最近 3 条 |

## 二、功能设计

### 2.1 智能每日推荐

**推荐因子与权重：**

| 因子 | 数据来源 | 逻辑 | 优先级 |
|------|---------|------|--------|
| 时段 | `new Date().getHours()` | 6-10 早餐，11-14 主菜/汤，15-17 甜品/小吃，18-23 主菜/汤 | 必选 |
| 星期 | `new Date().getDay()` | 周末推高热量/甜品，工作日推轻食/沙拉 | 必选 |
| 天气 | Open-Meteo（免费，CORS 友好） | <10°C 推汤/炖，>28°C 推沙拉/甜品 | 可选，降级 |
| 地区 | `navigator.geolocation` → 反向查询 | 法国推法餐，日本推日料 | 可选，降级 |

**稳定性**：同一天看到同一道菜，次日换菜。

```
种子 = hash(日期字符串)
推荐池 = 按时段 + 天气 + 地区过滤 dishKnowledgeDb
最终推荐 = 推荐池[种子 % 推荐池.length]
```

**降级链**：天气获取失败 → 纯时间+随机；定位失败 → 不限菜系。

**缓存策略**：
- 推荐结果缓存到 localStorage `dishlens_daily_rec_{YYYY-MM-DD}`
- 天气缓存到 localStorage `dishlens_weather_{YYYY-MM-DD}`
- 当天重复打开直接读缓存

### 2.1.1 后续迭代：位置餐馆推荐

**目标**：将首页「今日推荐」从单一道菜升级为「附近适合今天吃什么」。推荐不只看天气和时段，还结合用户当前位置，给出附近餐馆与适合点的食物方向。

**产品原则**：
- 外部地图 API 适合判断「附近哪家餐馆可能不错」，不适合直接断言「这家店今天哪道菜最好吃」。
- 具体菜品推荐仍应以 DishLens 的菜单识别结果为准。推荐链路应表达为：附近餐馆推荐 → 到店拍菜单 → AI 结合真实菜单推荐菜品。
- 文案避免过度承诺，例如使用「附近适合今天吃」「到店拍菜单后帮你选具体菜」。

**数据源建议**：

| 场景 | 主数据源 | 用途 |
|------|----------|------|
| 海外 | Google Places API | 附近餐馆、评分、评论数、距离、营业状态、价格等级、照片、餐馆类型 |
| 海外补充 | Foursquare Places API | POI 覆盖、类别、tips、照片、热度补充 |
| 国内 | 高德地图 POI / 腾讯位置服务 | 国内附近餐馆、餐饮类别、距离、营业信息 |
| 长期精准 | DishLens 自有数据 | 用户拍过的菜单、点过、收藏、评价、餐馆历史菜单 |

**第一版推荐逻辑**：
1. 用户授权定位。
2. 根据国家/地区选择数据源：海外优先 Google Places，国内优先高德或腾讯。
3. 拉取附近餐馆，过滤营业中、距离过远、评分/评论数过低的结果。
4. 结合时段、天气、饮食偏好生成推荐理由。
5. 首页卡片展示 1 个主推荐餐馆 + 1-2 个食物方向，例如「今天偏冷，附近这家法餐适合点汤品或炖菜」。
6. CTA 引导「到店拍菜单，帮你选具体菜」。

**第二版增强**：
- 同屏展示 3 个附近推荐餐馆。
- 加入菜系偏好、价格预算、步行距离、是否营业、是否适合多人/独食。
- 用户点开餐馆后，可查看「适合点什么类型」和「拍菜单后生成精确推荐」。

**第三版闭环**：
- 当用户在某餐馆拍过菜单后，沉淀餐馆名、城市、菜单菜品、点过菜、收藏、评价。
- 下次在附近时，优先推荐 DishLens 自有数据里的餐馆和菜品。
- 对未拍过菜单的餐馆，仍只做餐馆和菜系级推荐，不伪造具体菜名。

**待办优先级**：
1. P1：设计「附近推荐」数据结构和 API adapter，先支持 Google Places。
2. P1：新增定位权限说明与降级文案。
3. P2：国内数据源适配高德/腾讯。
4. P2：首页今日推荐卡片支持餐馆模式和菜品模式两种数据。
5. P3：结合点过/收藏/评价建立自有推荐排序。

### 2.2 翻译历史

**数据结构**：
```ts
interface HistoryEntry {
  id: string;              // 翻译任务 ID
  restaurant_name: string;
  city: string;
  dish_count: number;
  page_count: number;
  date: string;            // ISO 日期
  thumbnail: string;       // 第一道菜的图片 URL
  source_lang: string;
  target_lang: string;
}
```

**存储**：localStorage `dishlens_history`，最多保留 100 条。

**展示**：
- 按月分组（与当前 mock 渲染逻辑一致）
- 每条记录显示：缩略图 + 餐厅名 + 城市名 + 菜品数 + 日期
- 空状态：显示引导文案「拍摄第一份菜单开始吧」

**写入时机**：翻译完成（`status === "done"`）时自动存入。

### 2.3 菜品收藏

**数据结构**：
```ts
interface FavoriteDish {
  id: string;
  name_original: string;
  name_zh: string;
  cuisine: string;
  image_url?: string;
  saved_at: string;        // 收藏时间
}
```

**存储**：localStorage `dishlens_favorites`，不设上限。

**交互**：
- 菜品详情页心形按钮：点击切换收藏状态（实心/空心）
- 收藏页：卡片列表，点击进入详情；长按/点击心形移除
- 空状态：显示引导文案「翻译菜单时收藏感兴趣的菜品」
