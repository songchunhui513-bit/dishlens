# 项目经验

## 2026-08-10 - 视觉升级必须保留已确认的产品基线

- 在没有新的设计定稿时，不要用“提升可读性”为理由同时放大所有字号、卡片间距和装饰层级。
- DishLens 的菜单列表应保持安静、紧凑、便于快速扫读；新增图片状态、推荐和点单能力时，应沿用现有卡片结构，而不是重做视觉语言。
- 视觉修改必须提供前后截图并覆盖首页、菜单列表、详情页三条核心路径；功能改进与视觉重构应拆分提交，便于独立回退。
- 加载/识别状态不能只判断字段是否存在；数组结果必须验证 `length > 0`，终态必须分别处理成功、部分成功和全部失败。

## 2026-08-11 - 历史 UI 还原必须使用精确版本基线

- 用户指出“回到之前版本”时，先通过 Git 历史和关键页面特征定位唯一提交，再以该提交逐文件比对，不能根据记忆做近似还原。
- UI 与业务逻辑必须分层处理：恢复 JSX 视觉、文案和样式时，保留最新的识别状态机、缓存、图片兜底、分享渠道和错误处理。
- 一次视觉版本还原必须覆盖该版本的完整页面族，包括加载、首页、结果、详情、历史、收藏、点单和分享；只改三条主路径会留下混合视觉。
- 为历史视觉的关键识别特征增加回归测试，例如中央加载动画、细进度条和不存在阶段卡片，防止后续无意覆盖。
