# DishLens 全球菜单分享需求

日期：2026-05-27

## 背景

现有方案 A 原型已经验证了“把一份菜单结果转成可分享链接”的方向。下一步需要把它接入真实结果页和 `/share/[id]`，并从单一微信群场景扩展到全球常见分享场景。

国内用户通常会把链接发到微信好友、微信群或朋友圈；海外用户更常用 WhatsApp、Telegram、LINE、Facebook、X 以及手机原生分享菜单。因此分享能力不能依赖微信私有协议，也不能把“微信群”作为唯一入口。

## 目标

1. 结果页完成识别后，可以直接打开统一分享面板。
2. `/share/[id]` 公开页可以再次转发，形成二次传播。
3. 分享面板覆盖国内与海外主流渠道：发给朋友、复制链接、微信、WhatsApp、Telegram、LINE、Facebook、X。
4. 分享链接带有动态标题、摘要和 Open Graph 元数据，适配聊天软件预览卡片。
5. 微信入口采用“手机分享菜单或复制链接”的稳妥策略，不使用不可控的私有 deep link。

## 用户场景

### 国内聚餐

用户在餐厅拍菜单识别后，把结果发到微信群。群友打开 `/share/[id]` 后能看到菜品、价格、翻译和推荐理由，再自行选择。

成功标准：微信环境里不会出现死链或无效跳转；无法直接唤起微信时能复制链接。

### 海外旅行

用户在海外餐厅识别菜单后，通过 WhatsApp 或 Telegram 发给同行者。接收者打开链接后不需要登录即可查看菜单结果。

成功标准：WhatsApp、Telegram、LINE 链接能带上标题、摘要和 URL。

### 跨设备保存

用户希望稍后在电脑或另一个手机上看菜单，通过复制链接或手机原生分享菜单保存链接。

成功标准：复制链接有明确反馈；不把低频渠道放在首屏占位。

### 二次转发

接收者从 `/share/[id]` 页面继续转发给其他人。

成功标准：公开分享页与原结果页复用同一套分享交互，文案和链接一致。

## 功能范围

本期包含：

- 结果页分享按钮接入统一分享面板。
- `/share/[id]` 分享页接入统一分享面板。
- 分享链接和渠道 URL 生成逻辑抽成复用模块。
- 动态页面 metadata、Open Graph、Twitter summary。
- 全球渠道 UI 和成功/失败反馈。
- 回归测试覆盖链接生成、元数据和 UI 接线。

本期不包含：

- 多人协同点菜状态同步。
- 私有群成员权限管理。
- 微信 JS-SDK 配置、公众号签名和服务端票据刷新。
- 分享数据埋点看板。

## 验收标准

1. 结果页点击“分享菜单”会打开分享面板。
2. `/share/[id]` 点击“分享给朋友”会打开同一分享面板。
3. 分享面板包含发给朋友、复制链接、微信、WhatsApp、Telegram、LINE、Facebook、X。
4. 微信按钮不依赖私有 URL scheme；不可原生分享时复制链接并提示用户粘贴到微信。
5. 分享 URL 使用 `/share/{taskId}`。
6. `/share/[id]` 能生成与具体菜单相关的 title、description、openGraph 和 canonical。
7. `node --test tests/logic-regressions.test.mjs`、`npm run lint`、`npm run build` 通过。
