# DishLens 点单与点过功能需求文档

日期：2026-06-03

## 1. 背景

用户完成菜单翻译后，下一步不只是“看懂菜”，而是要真正点菜。旅行场景里，用户通常需要在翻译结果里挑选几道菜，再把原语言菜名和数量展示给店员。吃完后，用户还需要回到这次点过的菜里评价，形成自己的餐厅/菜品记忆。

## 2. 目标

在不影响现网 H5 主视觉和已有功能的前提下，新增一条闭环：

菜单翻译完成 → 选择菜品 → 给店员核对 → 保存到点过 → 回看本次点过 → 评价菜品/餐厅。

## 3. 用户与场景

主要用户是海外旅行者、留学生、出差人群。他们在餐厅面对外语菜单，需要快速理解菜品、选出想吃的内容，并把店员能看懂的原文菜名展示出来。

关键场景：

- 菜单翻译完成后，用户在列表里快速选 1 到多道菜。
- 用户进入菜品详情页查看风味、过敏原、建议，再把这道菜加入本次点单。
- 用户选好后生成“给店员确认”的页面，店员看到原语言菜名、数量和备注。
- 如果菜单没有拍到价格，页面明确显示“价格待核对”，不误导用户。
- 用户确认已点后，把本次记录保存到“点过”。
- 吃完后，用户可以从首页底部“点过”进入历史点单，评价餐厅或具体菜品。

## 4. 信息架构

首页底部导航扩展为：

- 历史
- 收藏
- 点过
- 设置

新增页面：

- 点单确认页：展示给店员核对。
- 点过页：按餐厅/就餐批次聚合用户点过的记录。
- 点过详情页：复用翻译结果列表卡片，展示这次点过的菜品。

## 5. 功能需求

### 5.1 首页入口

- 在现网首页底部导航新增“点过”入口。
- 不在首页主体新增点过卡片、功能说明或最近点过摘要。
- 入口样式与历史、收藏、设置保持一致。

### 5.2 翻译结果列表选菜

- 保持现网结果列表卡片结构。
- 每张菜品卡右侧新增轻量选择控件。
- 未选状态显示加号。
- 已选状态显示数量，悬停或触摸后可继续加减。
- 不新增顶部“几道菜品”统计。
- 不改变菜名、图片、标签、推荐文案的现有排版。

### 5.3 菜品详情点单模块

- 保持现网菜品详情主体不变。
- 底部新增点单模块，包含数量加减、当前选中摘要、进入点单确认页的按钮。
- 模块不得遮挡详情页原有正文和评价按钮。
- 点击加入或更新后停留在详情页，通过轻提示反馈“已加入/已更新”。

### 5.4 给店员确认页

- 以店员语言优先展示菜单原文菜名。
- 中文只作为用户自己核对使用。
- 展示数量、单价或价格待核对、参考总价。
- 支持备注快捷选择，并自动展示原语言备注。首批备注：
  - 不要花生
  - 不要香菜
  - 不要葱花
  - 少辣
  - 不要乳制品
  - 不要猪肉
- 主按钮文案为“我已点好，保存到点过”。
- 主按钮视觉保持温和，不使用过重的大绿按钮。

### 5.5 点过页

- 入口来自首页底部“点过”。
- 按餐厅/就餐批次展示记录。
- 卡片整卡可点击进入点过详情。
- 卡片展示餐厅名、地区/时间、已点菜品摘要、参考金额或价格待核对。
- 不展示“点过几次”。
- 不提供分享入口。

### 5.6 点过详情页

- 使用现网翻译结果列表卡片风格展示本次点过的菜。
- 每张菜品卡新增轻量“评价/已评”按钮。
- 点击菜品卡进入现有菜品详情。
- 点击评价进入现有评价流程；评价完成后返回点过详情，并把该菜标记为已评。

## 6. 非目标

- 不接账号体系。
- 不做服务端订单。
- 不向餐厅下单。
- 不改现有分享模块。
- 不重做首页、结果列表、详情页主视觉。
- 不发布现网，先本地研发和评审。

## 7. 数据策略

本阶段使用本地存储解决，不依赖账号：

- 当前点单选择保存在前端状态。
- 已点记录保存到 localStorage。
- 记录菜品快照，避免后续菜单历史被覆盖后无法回看。
- 价格无法识别时保存为未知，并在界面显示“价格待核对”。

## 8. 验收标准

1. 首页除底部新增“点过”外，主体视觉与现网一致。
2. 翻译结果列表除选择控件外，卡片布局与现网一致。
3. 菜品详情除底部点单模块外，主体视觉与现网一致。
4. 点单模块不遮挡现有按钮或正文。
5. 点单确认页可展示原文菜名、数量、备注和价格待核对状态。
6. 保存后“点过”页能看到本次记录。
7. 点过详情页卡片样式与翻译列表一致，并能进入菜品详情。
8. 点过详情页评价按钮可进入评价流程，完成后显示已评。
9. 393px 移动端视口无横向溢出、文字重叠、按钮遮挡。
10. 本地测试通过后仅提供本地演示，不自动发布现网。
